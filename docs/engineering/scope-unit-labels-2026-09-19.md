# Scope / Review unit labels — bounded correction

The integrated browser exercise found a UUID in the Unit column. The cause was the three `scope-router.ts` assembly mappers: each assigned `assemblies.defaultUnitId` to the engine's textual `defaultUnit`. The engine then persisted that text in generated scope items. This correction changes that boundary, not pricing or catalog ownership.

`listAssemblies({ includeUnitLabel: true })` now resolves the listed assemblies' exact default-unit UUIDs in one bulk lookup and returns `defaultUnitLabel` alongside the unchanged `defaultUnitId`. Count, assembly page and unit labels are read through one `repeatable read`, `read only` transaction, so a concurrent edit cannot mix an older assembly observation with a later unit label. A nonblank abbreviation is used first, otherwise the referenced unit's own nonblank name. A missing unit/reference/label stays unresolved. Ordinary `listAssemblies` callers retain their raw result shape and read path without the extra lookup/transaction. Existing priced-component helpers keep their own transactions and are not called or nested by this list operation. Units are read as existing metadata; this does not classify them as canonical or tenant-owned.

Generate, preview and regenerate use the resolved text. An unresolved value is carried as an empty string rather than an assumed `EA`, preventing the existing engine's null fallback from inventing a unit at this boundary. The Scope and Review tables share a small presentation component: a known label is shown, while an empty value or UUID left in an older draft displays **Unit needs review**. There is no rewrite/backfill of earlier drafts or approved snapshots, and no inference from an assembly name. Operators must resolve the source definition and review/regenerate a draft when appropriate.

The marker is presentation, not a new approval/export guard. This change does not claim to close the broader G4b catalog/authorization work, change legacy snapshot semantics, validate all physical unit meanings, or prove production behavior. In particular, preview/regenerate retain pre-existing global rule/catalog selection; this is not a G2 closure. It does not change the pricing adapter or the engine's other callers.

Validation used tests first: 17 expected failures with 22 existing passes, then 39/39 passes. Tests cover exact UUID lookup, one deduplicated query, raw-call compatibility, abbreviation/name resolution, missing references without `EA`, display of legacy UUIDs, and real-engine generate/preview/regenerate persistence. The related predecessor regression run passed **531/531 in 12 files**, including assembly pricing, scope generation/review/conversion, pipeline and the separate ownership-readiness tool. The subsequent transaction correction added three behavioral cases (all three failed before the correction): all queries on the transaction handle with explicit isolation/access mode, simulated concurrent unit change preserving the earlier snapshot, and transaction-start failure without unscoped fallback. After that correction, **91/91 tests passed** across unit labels, scope formula/boundary and component pricing, and `pnpm check --incremental false` passed with zero errors. The new unit coverage comprises 18 tests in `scope-unit-labels.test.ts` plus four boundary cases in `scope-formula-boundary.test.ts`. No browser or real-database concurrency claim is added by these component/server tests.
